# 后台管理端样式规范

> 版本：1.2.0
> 适用范围：`web/src/components/admin`、`web/src/components/layout/components`、`web/src/features/admin`、`web/src/features/usage-logs` 及复用工业风样式的管理端页面
> 规范来源：当前实现中的 `web/src/styles/admin-theme.css`、`web/src/styles/theme.css`、`web/src/styles/theme-presets.css`、`web/src/styles/index.css`、后台布局组件、频道/用户/仪表盘/日志模块

## 1. 设计定位

后台采用 **Obsidian Industrial Console（黑曜石工业控制台）** 视觉语言：

- **黑底、硬边、零圆角**：以深黑画布和 1px 锐利分隔线建立控制台秩序。
- **单色高亮**：默认主操作使用纯白，避免大面积彩色装饰；颜色主要用于状态和风险提示。
- **数据优先**：管理信息以等宽字体、表格、时间戳、路径和状态标签呈现，减少装饰性卡片。
- **终端感**：标题、导航、筛选器、表头和状态使用小字号、全大写、字距拉开，形成命令行式信息层级。
- **克制动效**：仅保留颜色、透明度和边框变化；不使用会干扰数据阅读的复杂动画。

后台页面必须优先传达：**当前位于哪里、系统是否正常、正在管理什么、下一步可执行什么操作**。

## 2. 主题范围与实现边界

### 2.1 后台主题入口

- 全局样式入口：`web/src/styles/index.css`
- 后台工业风覆写：`web/src/styles/admin-theme.css`
- 旧版/独立后台布局参考：`web/src/components/admin/admin-layout.tsx`
- 当前认证控制台外壳：`web/src/components/layout/components/admin-console-shell.tsx`
- 页面内容包装器：`web/src/components/admin/admin-page.tsx`

`admin-theme.css` 当前通过 `!important` 和全局 `* { border-radius: 0 }` 强制统一视觉。该文件在 `index.css` 中最后导入，且变量覆盖使用 `!important`，因此会覆盖普通主题和大部分预设颜色。注意：当前选择器是全局的，并未用 `.admin` 容器限定；它实际可能影响认证控制台之外的页面。新增后台页面应优先复用现有主题变量和组件类，不要在局部重新定义另一套黑色、边框或圆角规则。若未来要将工业风严格限制到后台，应先增加明确的后台根节点作用域，再迁移这些全局规则。

### 2.2 推荐页面结构

```text
AdminShell / AdminLayout
├── Sidebar：品牌、分组导航、用户信息
├── Header：路径、系统状态、主操作
└── Main
    └── AdminPage
        ├── Page heading：标题、描述、页面操作
        └── Content：筛选器、批量工具栏、统计、表格、空状态
```

### 2.3 外壳选择与布局职责

- `/ _authenticated` 路由当前实际挂载 `AdminLayout`，因此 `AdminLayout` 是当前可见的工业终端外壳和视觉基准。
- `AdminConsoleShell` 是基于 `@chaos_team/chaos-ui/layout` 的共享控制台外壳候选/替代实现，负责侧栏、顶部业务工具区、用户菜单、通知、语言切换和外观配置入口；若切换路由挂载关系，必须重新核对间距、折叠态和主题覆盖。
- `AdminLayout` 负责显式的 256px 侧栏、64px 顶栏、PATH 面包屑、服务器状态和 `Deploy New` 操作；新页面不要在两套外壳之间重复实现这些全局 chrome。
- `AdminPage` 只负责页面级标题、描述、操作区和内容间距，不负责请求、权限、筛选或表格逻辑。
- 认证控制台的内容外壳当前设置 `contentPadding={false}`，页面组件应自行控制内容内边距；不要同时在外壳和页面重复添加大块 padding。
- 侧栏存在折叠态，品牌需要同时提供完整 logo 和单字母/紧凑 logo；折叠后导航仍必须通过 tooltip、可访问名称或其他方式保持可理解。

## 3. 设计令牌

### 3.1 核心颜色

以下为当前后台主题的稳定基准值。Tailwind 类名中的 `zinc` 值应与这些语义保持一致；新增组件优先使用 `var(--admin-*)` 或语义化主题变量，而不是随意增加新色值。

| 语义 | CSS 变量 | 当前值 | 使用场景 |
| --- | --- | --- | --- |
| 画布黑 | `--admin-bg-color` | `#0a0a0a` | 页面、侧栏、主内容区背景 |
| 卡片黑 | — | `#0f0f0f` | 锐利卡片、弹窗内容、强调容器 |
| 次级黑 | — | `#0c0c0c` | 表格分页栏、底部工具区 |
| 表头黑 | — | `#18181b` / `zinc-900` | 表头、次级控件背景 |
| 主文字 | — | `#e5e5e5` | 正文、数据、页面默认前景 |
| 强调文字 | `--admin-accent-color` | `#ffffff` | 主标题、选中项、主按钮 |
| 次级文字 | `--admin-text-secondary` | `#737373` | 描述、导航未选中、辅助数据 |
| 弱文字 | — | `#52525b` / `zinc-600` | 分组标签、空状态、时间轴 |
| 边框 | `--admin-border-color` | `#262626` | 主分隔线、卡片、输入框、表格 |
| 边框悬停 | — | `#404040` | 卡片和次级按钮悬停 |
| 聚焦环 | — | `#52525b` | 键盘焦点/输入聚焦 |
| 成功 | — | `#10b981` / `emerald-500` | 在线、启用、成功响应 |
| 风险/错误 | — | `#ef4444` / `red-500` | 自动禁用、删除、失败响应 |
| 警告 | — | `#f59e0b` / `amber-500` | 未授权、需要注意的状态 |
| 信息/请求方法 | — | `#60a5fa` / `blue-400` | HTTP 方法、辅助信息 |

### 3.2 颜色使用规则

1. 页面背景只使用 `#0a0a0a`；容器背景使用 `#0f0f0f`，分页或底部辅助区域使用 `#0c0c0c`。
2. 纯白只用于品牌、当前导航、主标题、关键数字和主按钮，不作为大面积装饰。
3. `zinc-500` 及以下只用于辅助信息，不能承载唯一的关键业务含义。
4. 成功、错误、警告可以使用颜色，但必须同时提供文字或图标语义，不能只靠颜色区分。
5. 不为每个页面单独创建新的蓝、灰或黑色；若语义一致，直接复用本表值。
6. `::selection` 使用白底黑字，保持与后台反差风格一致。

### 3.3 主题设置优先级

- `data-theme-preset`、`data-theme-font`、`data-theme-radius`、`data-theme-scale` 和 `data-theme-content-layout` 由主题提供器写入 `body`，用于普通主题的配色、字体、圆角、密度和内容布局切换。
- 后台工业主题当前位于全局层，并使用 `!important` 固定背景、主色、边框和半径；因此后台规范中的黑白硬边规则优先于普通主题预设。新增后台组件不应假设用户选择的普通 preset 会改变工业主题的核心黑白结构。
- `data-theme-radius` 的普通可选值为 `none=0`、`sm=0.3rem`、`md=0.5rem`、`lg=0.75rem`、`xl=1rem`；后台工业主题固定为 0，不应根据这些值重新引入圆角。
- `data-theme-scale` 可改变普通界面的文字和间距，但后台组件的核心尺寸应保持本规范定义的可读性和触控目标；不要用紧凑密度把输入控件压到移动端不可用。
- 宽屏内容可使用 `centered` 布局，在 `1280px` 以上将内容限制到默认 `1280px`；需要展示宽表格、日志或复杂配置时可保留 `full`。

## 4. 字体与排版

### 4.1 字体角色

| 角色 | 字体 | 用途 |
| --- | --- | --- |
| UI 无衬线 | `Space Grotesk` | 后台默认正文、导航、按钮和布局文字 |
| 数据/命令等宽 | `JetBrains Mono` | 代码、ID、路径、时间、金额、指标、表格、状态标签 |
| 回退 | `-apple-system, BlinkMacSystemFont, 'Segoe UI', Roboto, sans-serif` | 系统无衬线回退 |
| 等宽回退 | `ui-monospace, SFMono-Regular, Menlo, Monaco, Consolas, monospace` | 等宽字体回退 |

- 字体由 `admin-theme.css` 通过 Google Fonts CSS 引入 `Space Grotesk` 与 `JetBrains Mono`；全局 `index.css` 同时加载 Public Sans 和 Lora，但工业后台应以 Space Grotesk / JetBrains Mono 为准。
- 后台工业风样式目前是全局覆盖，并不只挂在 `.admin` 容器下；因此本文的“后台规范”描述的是后台目标视觉，实际落地时还要注意它可能影响登录、钱包或其他非后台页面。

后台数据密集区域必须使用 `.mono` 或 Tailwind 的 `font-mono`。普通说明文字可使用 Space Grotesk，但同一个组件中不要无目的地混用多套字体。

### 4.2 字号、字重与字距

| 层级 | 规格 | 用途 |
| --- | --- | --- |
| 页面标题 | `18px`、`font-bold`、全大写、`tracking-tight` | `AdminPage` 标题 |
| 区块标题 | `12px`、`font-bold`、全大写、约 `0.2em` 字距 | 图表、状态、日志区块 |
| 正文/表格 | `12px` | 表格内容、筛选器、按钮文字 |
| 描述 | `12px`、`#737373` | 页面说明、弹窗说明 |
| 标签 | `10px`–`11px`、全大写、`tracking-widest` | 导航分组、统计指标名称、状态辅助信息 |
| 核心数字 | `30px`–`36px`、`font-light`、等宽 | 余额、请求数、延迟、RPM/TPM |
| 微型标签 | `10px`、等宽、全大写、`letter-spacing: 0.05em` | `.status-tag` |

- 数值列、货币、配额、时间戳应启用 `font-variant-numeric: tabular-nums`。
- 页面标题和区块标题使用全大写时，文案仍必须通过 i18n 提供，不要把英文硬编码作为唯一语言。
- 内容过长时优先使用 `truncate` 或合理换行，避免撑破表格和侧栏。

## 5. 间距与尺寸

### 5.1 布局尺寸

| 对象 | 规格 |
| --- | --- |
| 侧栏宽度 | `256px`（`w-64`）或由当前 `AdminShell` 响应式控制 |
| 侧栏内边距 | `24px`（`p-6`） |
| 顶栏高度 | 独立工业布局为 `64px`（`h-16`） |
| 主内容内边距 | 独立工业布局为 `32px`（`p-8`）；共享外壳按 `AdminShell` 配置 |
| 页面区块垂直间距 | 页面级约 `24px`；大区块可使用 `32px`–`64px` |
| 表格单元格水平内边距 | `16px`（`px-4`） |
| 表格普通行垂直内边距 | `14px`（`py-3.5`） |
| 表头/分页行垂直内边距 | `12px`（`py-3`） |
| 筛选器容器内边距 | `16px`（`p-4`） |
| 批量工具栏内边距 | `12px`（`p-3`） |
| 控件标准高度 | `36px`（`h-9`） |
| 紧凑控件 | `28px`–`32px`（`h-7`/`h-8`） |
| 页面内容最大宽度 | 可使用 `max-w-container`（`1280px`）或 `max-w-container-lg`（`1536px`） |

### 5.2 响应式规则

- 移动端优先，筛选器和批量工具栏允许换行：`flex-wrap`。
- 表格不强制压缩列宽；使用横向滚动容器和 `.admin-no-scrollbar`，保留可读的最小列宽。
- 页面标题和操作区在窄屏上下排列，宽屏水平对齐。
- 统计指标在小屏单列，中屏以上使用多列网格。
- 移动端 `input`、`select`、`textarea` 应保持至少 `16px` 字号，避免 iOS 聚焦时自动缩放；后台内部的紧凑文字仍可用于标签和非输入内容。
- 触控目标不得仅依赖 10px 微型文字；可点击按钮仍需提供足够的可操作面积和清晰焦点。

## 6. 形状、边框与层次

### 6.1 形状规则

- 后台默认 `border-radius: 0`。
- `admin-theme.css` 当前通过 `* { border-radius: 0px !important; }` 强制零圆角；新增后台页面不得引入 `rounded-md`、`rounded-lg` 等圆角类来表达层级。
- 头像、品牌标记、弹窗、输入框、下拉菜单、按钮、标签、表格和卡片均保持方角。

### 6.2 边框规则

- 默认使用 `1px solid #262626`。
- 分隔线使用单边框：页面标题区 `border-b`、顶栏/侧栏 `border-*`、区块标题 `border-t`。
- 表格外框、表头底线、分页顶部线必须连续且对齐。
- 禁止用厚重阴影替代结构边框；当前工业主题不使用常规卡片阴影。
- `.border-thin` 表示通用 1px 边框；`.sharp-card` 表示 `#0f0f0f + 1px #262626` 的锐利卡片。

### 6.3 层次规则

从低到高依次为：

```text
#0a0a0a 画布
→ #0c0c0c 辅助底栏
→ #0f0f0f 卡片/弹窗
→ #18181b 表头/次级控件
→ #262626 边框
→ #ffffff 主操作/当前状态
```

不使用渐变、玻璃拟态或大面积发光效果作为后台核心层次。数据区用留白和细线建立节奏。

> 实现例外：`web/src/styles/index.css` 还为通用 `[data-slot='card']` 提供了全局 hover 上移 `1px` 和阴影规则；这不是工业后台的推荐卡片表达。后台新增 `.sharp-card` 或统计区应保持零阴影、零位移，若直接复用通用 Card，必须先确认其 hover 行为不会破坏工业层次。

## 7. 核心组件规范

### 7.1 侧栏导航

- 侧栏使用 `#0a0a0a`，右侧 1px `#262626` 分隔。
- 品牌标记为 `20px × 20px` 白色方块，内部 `10px × 10px` 黑色方块。
- 品牌主字使用等宽、`12px`、粗体、较宽字距；副标签使用 `9px`、灰色、全大写。
- 分组标题使用 `10px`、`zinc-600`、全大写、`tracking-widest`。
- 导航项使用 `12px` 等宽字体，垂直间距约 `12px`。
- 默认状态：`zinc-500`；悬停：白色。
- 激活状态：左侧 `2px` 白色指示条、白色文字、`font-medium`，可配极弱的从左到右白色透明渐变。
- 激活状态必须有文字、边框或 `aria-current` 等非颜色反馈。

### 7.2 顶栏与页面头部

- 顶栏显示当前位置，采用 `PATH: SECTION / PAGE` 的等宽、全大写格式。
- 当前页面路径使用 `zinc-300`，前缀使用 `zinc-500`。
- 系统状态使用 `6px × 6px` 的绿色方块加文本，例如 `SERVER: OPTIMAL`。
- 页面头部使用下边框和 `pb-4`，标题与描述垂直排列。
- 右侧主操作靠右对齐，避免与标题抢占视觉焦点。

### 7.3 主按钮

类名：`.btn-industrial-primary`

```css
background: #ffffff;
color: #000000;
padding: 4px 12px;
font-size: 12px;
font-weight: 700;
text-transform: uppercase;
letter-spacing: -0.025em;
```

- 用于创建、保存、部署等正向主流程。
- 悬停背景变为 `#e4e4e7`。
- 图标与文字间距 `6px`。
- 不使用彩色主按钮；白色即为最强操作层级。

### 7.4 次按钮

类名：`.btn-industrial-secondary`

- 透明背景，1px `#27272a` 边框，文字 `#d4d4d8`。
- 悬停边框变为 `#52525b`，文字变白。
- 用于筛选、取消、翻页、启用/禁用等次级操作。
- 保持等宽、`12px`、全大写；与主按钮高度一致。

### 7.5 危险按钮

类名：`.btn-industrial-danger`

- 透明背景，文字 `#ef4444`，边框为 `rgba(239, 68, 68, 0.4)`。
- 悬停边框变为 `#ef4444`，背景为 `rgba(239, 68, 68, 0.1)`，文字变为 `#f87171`。
- 仅用于删除、永久清理等不可逆操作。
- 破坏性操作必须通过确认弹窗二次确认，并明确说明影响范围。

### 7.6 锐利卡片与统计区

类名：`.sharp-card`

- 背景 `#0f0f0f`，边框 1px `#262626`，零圆角。
- 悬停只改变边框为 `#404040`，不进行明显位移或阴影放大。
- 统计区可使用无卡片背景的分栏布局，以顶边框和充足留白组织内容。
- 指标名称：`11px` 左右、全大写、`tracking-widest`、`zinc-500`。
- 指标数值：`30px`–`36px`、轻字重、白色、等宽。
- 单位使用 `zinc-600`，不要与核心数值竞争。

### 7.7 表格

- 外框：1px `#262626`，背景 `#0a0a0a`。
- 表格使用 `12px` 等宽字体、左对齐、`whitespace-nowrap`。
- 表头：`#18181b` 背景、`zinc-500` 文字、全大写、底部 1px 边框。
- 表头和单元格统一 `px-4`；表头 `py-3`，内容行 `py-3.5` 或 `py-4`。
- 行分隔线使用 `zinc-900`；悬停使用 `rgba(39,39,42,0.5)` 对应的 `hover:bg-zinc-900/50`。
- 主标识（用户名、频道名、路径）使用白色或 `zinc-300`；辅助字段使用 `zinc-400`；ID、时间和弱元信息使用 `zinc-500`。
- 数字和金额列启用等宽数字；金额、比例、响应时间等右对齐。
- 加载和空状态使用 `py-12`、居中、`zinc-600`，并提供明确文本。
- 表格容器在小屏横向滚动；不要通过过小字号破坏可读性。

### 7.8 表格分页

- 分页栏使用 `#0c0c0c` 背景、顶部 1px `#262626`，`12px` 等宽字体。
- 当前页、总页数和总数使用白色；说明文字使用 `zinc-500`。
- `PREV` / `NEXT` 复用次按钮。
- 不可用时降低到 `opacity: 0.3`，同时设置 `disabled` 和 `cursor-not-allowed`，不能只靠透明度表达禁用。

### 7.9 筛选器与输入控件

- 筛选器容器使用 `.sharp-card`、`p-4`、`gap-3`，允许多行换行。
- 输入框、选择器、下拉菜单使用 `#0a0a0a` 背景、`#262626` 边框、零圆角、`12px` 等宽字体。
- 标准高度 `36px`；占位符为 `zinc-600`，输入文字为 `zinc-200`/`zinc-300`。
- 搜索、重置等操作使用次按钮，并配合清晰的图标与文字。
- 聚焦时必须有可见的边框或焦点环；错误状态使用红色边框/焦点环及字段错误文案。

### 7.10 状态标签

类名：`.status-tag`

- 等宽字体、`10px`、全大写、`letter-spacing: 0.05em`。
- 1px `currentColor` 边框，水平 `4px`、垂直 `1px` 内边距，行高约 `1.2`。
- 标签颜色：成功 `emerald-500`，错误 `red-500`，未知/禁用 `zinc-500`。
- 状态文字应短、稳定、可翻译；必要时加 `aria-label` 或隐藏辅助文本。

### 7.11 弹窗与表单

- 内容面板使用 `#0f0f0f`、1px `#262626`、白色文字、零圆角。
- 标题使用 `16px` 等宽字体；说明使用 `12px`、`zinc-500`。
- 表单字段纵向间距约 `16px`；字段标签使用 `12px` 等宽、`zinc-400`。
- 弹窗底部操作区使用顶部 `#18181b`/`#262626` 分隔线和 `pt-2`，按钮顺序为取消在左、保存/确认在右。
- 长表单弹窗最高约视口 `85vh`，内容区域可滚动。
- 提交中必须禁用主按钮并保留明确的加载反馈。

### 7.12 图表与日志

- 图表优先使用线条、柱体、顶边框和坐标标签，不使用厚重背景卡片。
- 普通柱体为 `zinc-800`，悬停为 `zinc-700`，当前峰值为白色。
- 图表标签为 `9px` 等宽；悬停提示使用 `#18181b` 背景、`#52525b` 边框、`zinc-300` 文字。
- 日志路径和时间使用等宽字体；HTTP 方法可使用蓝色，成功使用绿色，错误使用红色，未授权使用琥珀色。
- 状态必须同时显示文本，例如 `200 OK`、`500 ERR`，不得只显示颜色点。
- 仪表盘无数据时当前会保留低高度占位柱和示例日志行；真实业务页面应明确区分“暂无数据”和演示/占位内容，避免将静态示例误认为实时数据。
- 仪表盘中的实时执行日志当前未独立包裹横向滚动容器；新增或重构移动端日志表时必须补充横向滚动或卡片降级，不能依赖桌面端宽度。

### 7.13 日志辅助组件

- 日志状态标签可复用 `LogStatusTag`，根据状态使用 `success`、`error`、`primary` 或 `default` 语义颜色；未知状态必须回退到中性样式。
- 日志类型徽章优先使用现有 `Badge` 变体，无法匹配时使用 `outline`，不要为单个日志类型创建新的颜色体系。
- 可复制文本使用等宽小字号、单行截断和悬浮完整值；复制按钮使用小尺寸 ghost 图标按钮，并提供可访问名称。
- ID、模型名、路径、提示词等长文本必须有溢出策略（截断、换行或横向滚动），同时保留查看完整值的方式。

### 7.14 标签页与行级操作

- 日志分区标签页使用底部边框作为轨道，标签之间保持约 `24px` 间距；默认文字为 `zinc-500`，悬停为 `zinc-300`，激活态为白色、粗体并使用 `2px` 白色底边。
- 标签页的激活状态必须同步提供可访问状态（如 `aria-selected`、合适的 tab 语义或等价的当前导航标识），不能只依赖白色底边。
- 表格行级操作优先使用 `ghost` 图标按钮：频道使用 `icon-xs`，用户使用 `icon-sm`；按钮之间仅保留紧凑间距，避免挤压数据列。
- 图标按钮必须同时提供 `aria-label` 和必要时的 tooltip/title；删除、重置密钥、重置双因素认证等不可逆或高风险操作必须使用确认交互。
- 异步操作进行时应禁用相关操作按钮，避免重复提交；成功和失败结果使用统一 toast，并通过 i18n 提供文案。

## 8. 交互与动效

- 普通颜色、边框和透明度过渡使用 `120ms`–`300ms`，推荐 `ease-in-out`。
- 按钮激活可使用轻微 `scale(0.98)`，不得产生明显跳动。
- 卡片悬停只允许轻微边框变化；管理端数据表不使用大幅位移。
- 滚动条保持深色、细窄：宽高约 `5px`，轨道 `#0a0a0a`，滑块 `#262626`，悬停 `#404040`。
- 需要隐藏滚动条时仅用于横向表格或导航等明确场景，使用 `.admin-no-scrollbar`，不要禁用滚动本身。
- 必须遵守 `prefers-reduced-motion: reduce`：减少或关闭装饰动画，保留可理解的最终状态。

## 9. 无障碍与内容规范

- 交互元素使用原生 `button`、`a`、`input`、`select` 或具备完整键盘行为的 UI 组件。
- 所有图标按钮必须有可访问名称；表格复选框必须有 `aria-label`。
- 当前导航使用 `aria-current` 或等价状态，不只依赖左侧白色指示条。
- 焦点状态必须可见，不能被黑色背景吞没。
- 正文和关键状态满足 WCAG 2.1 AA 对比度；`zinc-600` 仅用于非关键辅助文字。
- 用户可见文案全部走 i18n；状态、按钮、空状态、错误和确认描述均不得硬编码为单语言。
- 危险操作说明影响对象、不可逆后果和确认动作。

## 11. 状态矩阵

所有后台数据型组件至少定义以下状态，并保持结构稳定：

| 状态 | 视觉表现 | 行为要求 |
| --- | --- | --- |
| 默认 | 画布/容器正常层级 | 提供完整可读内容 |
| 悬停 | 边框变亮或行背景变为 `zinc-900/50` | 不改变布局尺寸 |
| 聚焦 | 可见 `ring` 或边框变化 | 键盘可到达、焦点顺序合理 |
| 激活/选中 | 白色文字、白色底边或 `zinc-900/30` 背景 | 同步暴露语义状态 |
| 禁用 | `opacity: 0.3` 左右、弱化颜色 | 必须真实 `disabled` 或 `aria-disabled` |
| 加载 | 维持容器结构，显示 `Loading...` 或骨架 | 防止重复提交；避免布局跳动 |
| 空数据 | 居中 `py-12` 辅助文案 | 明确说明暂无数据，不伪装成错误 |
| 错误 | 红色语义提示或错误区域 | 提供可理解错误信息和恢复/重试入口 |
| 破坏性确认 | Popconfirm/Dialog | 说明影响、不可逆性和确认动作 |

## 13. 维护与变更规则

- 新增颜色、字号、间距或组件类前，先确认现有令牌和 `@chaos_team/chaos-ui` 组件不能满足需求。
- 修改 `admin-theme.css` 时必须评估其全局影响，尤其是 `:root`、`.dark`、`body`、`*`、全局滚动条和 `!important`。
- 若调整主背景、边框、字体或圆角，必须同步更新本文件的令牌表、组件章节和验收清单。
- 若切换当前路由的外壳挂载，必须复核侧栏折叠、顶栏高度、内容 padding、焦点管理和移动端滚动。
- 不将备用或未挂载的 ProTable 列配置当作当前页面的实际尺寸；文档中的尺寸应来自实际渲染路径。
- 不把普通主题的 preset、radius、scale 选项误写成后台工业主题的视觉结果；后台当前由全局工业覆写固定核心黑白结构。

## 14. 现有实现备注

当前仓库同时保留两套认证后台外壳实现：

1. `AdminLayout` 当前由 `web/src/routes/_authenticated/route.tsx` 实际挂载，是当前路由可见的工业终端外壳，包含明确的 `#0a0a0a`、`#262626`、`Space Grotesk`、`JetBrains Mono` 和 PATH/Server 状态栏。
2. `AdminConsoleShell` 使用 `@chaos_team/chaos-ui/layout` 的 `AdminShell`，提供另一套共享控制台组合方式；它当前由 `AuthenticatedLayout` 组合，但不应在新增页面中与 `AdminLayout` 重复叠加。

本规范提取的是两者已经形成的共同后台视觉语言，并以 `admin-theme.css` 的工业风实现为基准。后续若继续统一后台，建议先明确唯一的路由挂载外壳，再将硬编码的 `bg-[#0a0a0a]`、`border-zinc-800`、`text-zinc-*` 逐步收敛为语义变量或共享组件，但不要在迁移过程中改变本规范定义的视觉结果。
